Why so many dashes — and why that is the point.
A dash means the app never asks that question for that page. Export is only ever asked on MRN. Delete is only ever asked on MRN. Import is only asked on Import OBD, Sampling Library, and the CSV buttons on the master-data screens. Showing a live checkbox everywhere would let you switch things on that do nothing — which has already happened: eight Export grants are switched on in the database right now and none of them does anything. The dash is the screen telling you the truth instead.
Two things this screen cannot fix on its own.
1. The Picking tab. It is part of the Mail Orders page, not a page of its own, so it has no row here. Giving it its own key is small and contained, and then it appears as a row like any other.
2. Mail Orders does not check permissions when saving. — FIXED 2026-08-30, corrected here 2026-09-04. This said: "Eleven of its save routes ask only 'are you logged in'. So unticking Edit on Mail Orders would hide the buttons but not block the save." That was true when the mockup was drawn on 2026-08-30 and was fixed the same day, in commit 0f56eede — all eleven routes now carry the same checkAnyPermission(roles, "mail_orders", "canEdit") block the other 37 write routes use, and backfill-enrich's unauthenticated GET was closed with them. Nobody lost access: every person holding mail_orders canView also holds canEdit. Two later sessions read this line and repeated it as current, which is why it is struck through and dated rather than deleted — a mockup is a record of its own date, and a silently edited one teaches nothing.
Users — with the three things that were missing. Phone (a real login identifier that most users already have), second roles (today only writable by hand in the database), and the two rollout flags.
