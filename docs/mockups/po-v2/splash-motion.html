Splash motion, four ways

The app already shows a wordmark while the catalogue loads. This replaces it with a white screen, the mark in brand violet, and a line that passes fast underneath. Four readings of "passes fast", with Trail chosen and no tagline. Every version is CSS only, and each runs while the data loads — the splash closes when the catalogue is ready, never when the animation ends.

What fires when

Timings for Trail. The mark is readable at 380 ms and the line has landed by 640 ms. Nothing waits on anything: if the catalogue is ready at 300 ms the splash closes at 300 ms, mid-animation, and that is correct behaviour.

Why there is no tagline

"Taking efficiency into a new orbit" was tried here and dropped. The splash has no fixed length — it lives exactly as long as the catalogue takes to load, which is a few hundred milliseconds on a warm cache and a couple of seconds on a cold one. A tagline that fades in at 700 ms would therefore appear roughly half the time, and a line that shows only sometimes reads as a fault rather than as branding. Holding the splash open long enough to guarantee it would mean slowing the app on purpose to show a slogan to its own staff.

Where the line belongs instead

The login page. It sits still until someone types, so the phrase gets read, and it is the one screen an outsider might see.

Or the board's empty state

Second best: the moment before the first product is added. Also stationary, but only staff ever see it.

Before any React gets written

Use the real wordmark

These frames approximate the mark with Outfit 800. The build must use the app's own Wordmark component, so the splash and the board can never drift apart.

The animation must not gate the load

The splash hides when the catalogue is ready, not when the animation ends. On a warm cache the user should see a flash and nothing more — never a forced wait for the line to finish.

Honour reduced motion

Under prefers-reduced-motion the screen shows its finished state instantly: mark, line, tagline, no movement. Built into this page, so you can test it here.

White, not the gradient

Today's splash is a white wordmark on the violet gradient. This replaces it. The gradient token stays where it is — nothing else uses the splash's copy of it, but check before deleting.

Transform and opacity only

Nothing animates width, height or layout, so the phone has no work beyond compositing. Trail animates left on a 6px dot — the one exception, and cheap at that size.

The motion, ready to lift

Trail, stripped to what the component needs. Three layers sit under the word: a solid rule that is the end state, a gradient tail that grows and fades, and the dot that pulls it. Colours come from the app's own tokens, not these literals.

@keyframes orbitRise  { from { opacity:0; transform:translateY(9px) } to { opacity:1; transform:none } }
@keyframes orbitRun   { 0%   { left:0;    opacity:0 }
                        12%  { opacity:1 }
                        88%  { opacity:1 }
                        100% { left:100%; opacity:0 } }
@keyframes orbitTail  { from { transform:scaleX(0) } to { transform:scaleX(1) } }
@keyframes orbitFade  { to   { opacity:0 } }
@keyframes orbitRule  { from { opacity:0 } to { opacity:1 } }

.mark { animation: orbitRise .38s cubic-bezier(.2,.85,.25,1) both }

.dot  { animation: orbitRun  .42s cubic-bezier(.3,0,.25,1) .10s both }

.tail { transform-origin: left center;
        background: linear-gradient(90deg, rgba(124,58,237,0) 0%, var(--brand) 100%);
        animation: orbitTail .42s cubic-bezier(.3,0,.25,1) .10s both,
                   orbitFade .16s ease-in .44s forwards }

.rule { background: var(--brand);
        animation: orbitRule .18s ease-out .46s both }

@media (prefers-reduced-motion: reduce) {
  .mark, .dot, .tail, .rule { animation: none }
  .dot, .tail { opacity: 0 }   /* rule and mark stay at their finished state */
}
